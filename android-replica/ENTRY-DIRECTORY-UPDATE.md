# 进入阅读时静默刷新目录

## 行为

采用已确认的番茄进入阅读流程：缓存正文排版完成后，在独立工作线程强制请求一次最新目录。后续按用户要求增加“最后五章内每进入一章检查”的进度策略；它是本应用的扩展，不能视为已确认的番茄行为。同章翻页和重排不重复请求，没有目录轮询定时器。离开阅读使本轮回调失效，返回阅读重新检查一次。

仅当新目录在旧目录后追加章节、且原有章节 ID 顺序完全一致时，静默接入新目录。当前章节 ID、字符偏移、分页对象以及相邻章排版保留；不取消翻页手势，不重排当前正文。手势或菜单显示期间收到的结果暂存，在手势结束或菜单关闭时应用。目录缩短、插入或重排由原有显式刷新路径处理。

新增章节接入原有后续五章磁盘缓存队列；紧邻下一章由邻章预加载器优先取正文并排版。新增的全书页数元数据在后台更新。目录刷新失败不弹错误，同章不自动重试；进入下一章时可再次检查，末章主动检查及重试入口继续保留。

网络慢、正文预取失败或新章在本次进入检查之后才发布时，仍可能需要末章检查或短暂加载。本功能不保证任何情况下均无等待。

## 真机验证（2026-10-25）

设备：小米 6 / Android 9，原包名和签名覆盖安装，未清除用户数据。

`ReaderUpdateChecks` 专项 8 项通过：

1. 暂缓入口目录请求时，旧目录正文已显示且可阅读，没有加载横幅。
2. 受控旧目录 479 条，通过真实接口恢复为 484 条；当前布局对象、章节和字符偏移不变，后续五章均有正文缓存，紧邻新章完成排版。
3. 从旧目录末章翻入新章，复用准备好的页面；测试阻止前台正文获取后仍能成功翻入，loadToken 未改变，没有加载或检查更新提示。
4. 重复执行准备/入口检查并静置 65 秒，仍只有一次目录请求。
5. 受控目录失败后正文保持可读，没有错误横幅或重试循环。
6. 离开阅读后返回的迟到目录结果不更新旧阅读界面。
7. 受控手势窗口内暂存目录结果，收到真实手势结束所调用的 idle 回调后才应用。
8. 测试结束恢复原阅读位置。

真实接口在本次测试前已包含这五章；旧目录是受控截短的缓存，未等待或模拟作者在现场发布。首次执行在通过核心链路后，被测试辅助函数 `launchMain()` 的 ActivityMonitor 断言中断；修正为显式启动主页并等待 reader 暂停，完整重跑 8 项通过。未为测试修改生产逻辑。

现有 `ParityChecks` 真机回归通过，包括三页复用、无动画拖动零额外重绘、四种翻页模式提交和回退、手势期间延迟视觉更新及仿真几何。安装和所有测试前后对比：3 本书籍 ID、全部阅读位置字段、书签相同。独立测试包已卸载。

证据：`../research/entry-directory-update/results.json`、`parity-results.json`、`data-preservation.json`、`prepared.png`、`new-chapter.png`。

APK：`build/yuejie.apk`，SHA-256 `d7a564929ef112189a384eee461c87c315e9e08f071abc8fdb12c5095ab14bb7`，与手机安装的 base.apk 一致。包含此前段评换行修复和目录正倒序切换。

## 运行专项测试

先构建正式 APK，再运行 `tests/build-comments.ps1` 构建独立测试包。测试入口：

```
am instrument -w com.example.yuejie.commentchecks/com.example.yuejie.ReaderUpdateChecks
```

测试需要连接真实设备、原签名测试 APK 和网络。当前设备普通 shell 的输入注入受限，instrumentation 使用已有 root 权限启动。
