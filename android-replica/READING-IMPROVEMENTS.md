# 阅读狗 0.3：图标、预缓存、作者和阅读进度

## 实现

- 图标：深绿底、米白小狗与翻开的书，原生矢量；Android 8+ 自适应图标，旧版使用矢量图标。可编辑源与预览位于 `design/`，`generate_icon.py` 可重新生成。
- 阅读时提前缓存后续 5 章：下一章沿用相邻排版预加载，第 2–5 章由独立串行工作线程和接口实例写入 SQLite，避免额外缓存任务排在当前正文请求前。缓存命中跳过、不重复入队，切换章节取消旧窗口，离开阅读停止剩余预取，失败静默结束该轮。
- 内存排版仍只保留当前/上一/下一章；磁盘正文仍按最近使用淘汰，上限 50 MiB。正在进行中的网络请求可能在离开阅读后完成并保存结果。预取失败不会覆盖当前正文或出现空白阅读页。
- 最近阅读和书架均显示作者、真实章节标题、目录位置/总章节。目录序号来自本地阅读位置，不从标题提取；例如目录 611/611 对应标题“第609章 谈条件”，数字不同是目录条目顺序与章节标题编号不同。
- 未知作者显示“作者未知”，未知章节总数显示“总数待更新”；未读书籍显示“尚未阅读”，已知总数时一并展示。

## 真机验收

2026-10-25，小米 6 / Android 9 / API 28，root 覆盖安装，保留包名和签名。版本 0.3 / versionCode 3。

[14 项验证结果](tests/improvements/reading-dog-03-evidence/improvements-results.json)：

- Android 上 22 组协议向量一致，旧书架迁移、存储限额与书签回归通过。
- 预取边界、尾章裁剪、缓存跳过、窗口去重、取消/关闭、失败停止检查通过。
- 《持械入宋》从目录第 1/483 章恢复，后续 5 章最初有 4 章缺失，实际请求后全部进入 SQLite；仅相邻章存在排版结果。
- 新建接口实例，在测试线程禁止网络的情况下，后续 5 章均能读取，且无需初始化正文会话密钥。这验证了本地缓存读取路径；本轮未通过关闭手机全部网络来复测整个阅读流程。
- 作者与目录进度出现在单页主页；原始自适应图标和 MIUI 返回的图标均能渲染。MIUI 对 PackageManager 返回的图标使用 BitmapDrawable 包装。
- [数据对比](tests/improvements/reading-dog-03-evidence/data-preservation.json)：覆盖安装及测试前后 3 本书籍 ID 和全部阅读章节/原文偏移相同。测试实际打开《持械入宋》，因此最近阅读排序已正常更新。
- 已查看最终主页及手机渲染图标截图，无重叠或截断关键进度信息。测试 APK 已移除，正式 App 留在主页。
