# 正文图片修复

正文中的 U+FFFC 继续占用一个 UTF-16 字符，但阅读器改为在对应位置绘制独立图片块。章节和段落的原文字串不改写，因此书签、段评及同步进度不需要迁移。纯文本章节使用原来的排版参数。

## 接口与显示

后端同一次 HTML 遍历提取图片地址、可用尺寸和字符偏移，章节增加 `image_version: 1` 与 `images`。图片地址保留查询参数及 HTML 实体解码结果，不把远端 HTML 交给 WebView 执行。继续使用已有媒体代理的 HTTPS、域名、重定向、类型和大小限制。

图片块按已知比例预留空间；未知尺寸用 4:3，超长图片缩到一页正文区域内。加载后等比适配块内，不重新分页。当前页及相邻页自动加载；图片占位可点击重试、打开大图，双指缩放和拖动只作用于大图层。正文上的横向滑动保持翻页语义。

图片原文件独立缓存在 `cache/body-images`，上限 64 MiB，单文件最多 8 MiB。解码前读取尺寸，按最大边 4096 和最多 4M 像素采样；共享位图缓存上限 24 MiB。页面只保留适合实际绘制尺寸的快照，限制额外持有的像素量。下载并发为 2，队列最多 48，重复 URL 共用在途任务。动图显示首帧。

## 旧缓存与异步结果

含对象占位符但缺少新版图片元数据的旧章节按需重取。正文及段落身份、范围完全一致时才自动替换；上游变化时保留旧章节，通过阅读器通知确认刷新。离线和失败均保留旧缓存，可稍后点击重试。纯文本旧缓存无需联网迁移。

页面快照在拖动和翻页动画期间保持冻结，结束后才应用图片结果。页面重绑会清除旧图片快照，切章后的迟到结果只刷新当前有效片段。关闭阅读器或大图后不再回调对应界面。

## 2026-11-10 双指缩放测试排查

v0.28 段评发布期间记录的双指缩放失败已复现并定位为测试手势问题。原测试的双指跨度为 200、270、340、410、480 px；420 dpi 模拟器的系统最小缩放跨度为 446 px。只有最后一次 MOVE 达到识别门槛，该事件开始缩放识别后，测试随即 CANCEL，没有后续 MOVE 产生缩放倍率，故 zoom 保持 1。分别设置和不设置触摸屏来源都能复现；增大跨度且继续移动后可缩放。

修复仅涉及 `tests/ImageChecks.java` 和 `tests/build-images.ps1`，未修改正文图片实现或其他未提交功能：

- 等待预览窗口实际布局及缓存位图就绪，按系统缩放阈值和实际视图长边生成手势；坐标保持在视图内。
- 明确验证低于阈值不缩放、跨过阈值开始识别、继续移动才改变倍率，以及向内缩小、缩放后边界限制和退出清理。
- 使用 View 的触摸分发，保留触摸屏来源、手指 ID、两种抬起顺序和单调递增时间，完整结束 POINTER_UP / UP，替代原先取消手势及倒退时间的测试序列。
- 独立测试 APK 直接编译当前全部应用源码，不再引用可能过期的 `build/classes.jar`；测试包不含私有后端配置。

最终 60 项图片检查在同一 Android 模拟器的 160、420、640 dpi 下分别通过（包括 96 组纯文本分页对照、正文图绘制、缓存、书签与同步队列检查）。密度覆盖属于模拟器配置检查，不等同于多台实体设备验收；Android 24–28 的阈值读取兼容分支尚未运行验证。已恢复模拟器原有 420 dpi，未更改线上 APK、版本号或发布任何新版本。
